# Repository Guidelines

## Project Structure

This is the Week 5 Task 2 voice-activated Flask calculator website. The original Week 4 calculator in `Week4/section_1` must remain unchanged when working on this task. `app.py` serves the page and routes arithmetic at `POST /api/calculate` through the `Calculator` class in `custom_classes.py`; `templates/index.html` contains its markup, and `static/css/` and `static/js/` contain the styling and browser behavior. `speech.py` proxies Azure recognition and synthesis, while `static/js/speech.js` and `recorder-worklet.js` handle browser audio. `DOCUMENTATION.md` and `CODE_EXPLANATION.md` document usage and implementation. `main.py` demonstrates the original command-line calculation; `design/calculator.png` is the visual reference.

## Build, Test, and Development

Run commands from `Week-5-task-2`. Install the web dependencies with `python3 -m pip install -r requirements.txt`, then start the local Flask server with `python3 app.py`. Open `http://127.0.0.1:5000/` in a browser. No frontend build step is required.

- `python3 main.py` — run the original command-line calculator demonstration.
- `python3 -m py_compile app.py speech.py custom_classes.py main.py` — check Python modules for syntax errors.

Run backend tests with `python3 -m unittest discover -s tests -v` and JavaScript tests with `node --test tests/commands.test.mjs`. Keep backend tests in Python's standard `unittest` framework and mock Azure calls so automated tests require no credentials or network access.

## Coding Style

Follow standard Python conventions (PEP 8): four spaces for indentation, `snake_case` for methods and variables, and `PascalCase` for classes. Keep calculator operations as methods on `Calculator`, annotate arguments and return values where useful, and use clear exceptions for invalid operations. Avoid adding dependencies for functionality available in the standard library.

## Testing Guidelines

For changes to arithmetic or error handling, verify normal results and edge cases, especially division by zero. Run the demonstration and syntax check above. Tests should use descriptive names such as `test_divide_by_zero_raises_value_error` and should not depend on execution order.

## Commits and Pull Requests

Recent history uses short, task-oriented commit subjects (for example, `part3` and `section 1 – part 1`); keep new subjects concise and descriptive, preferably stating the change. Pull requests should explain the behavior changed, list verification performed, and include screenshots only when a visual asset or rendered output changes. Link a related issue when one exists.

## Configuration and Generated Files

The application loads the nearest `.env` in this folder or its ancestors. Azure Speech credentials must remain server-side and must never be printed or committed. `.env` and `.venv` are ignored by Git. Do not commit interpreter caches such as `__pycache__/` or generated bytecode. Keep the source image in `design/` if it is updated.
